# SonarQube Integration Guide

## Overview

This project uses SonarQube for comprehensive code quality analysis, including native code coverage reporting without external services like Codecov.

## Configuration

### SonarQube Project Settings

The project is configured in `sonar-project.properties` with the following key settings:

```properties
# Project identification
sonar.projectKey=npm-package-visualizer
sonar.projectName=NPM Package Visualizer
sonar.organization=louis-amoah-nuamah

# Source and test paths
sonar.sources=server/,client/src/
sonar.tests=server/__tests__/,client/src/**/*.test.js,client/src/**/*.spec.js

# Native coverage integration
sonar.javascript.lcov.reportPaths=coverage/lcov.info,client/coverage/lcov.info
```

### Coverage Integration

SonarQube natively supports LCOV coverage reports generated by Jest:

1. **Server Coverage**: Generated in `coverage/lcov.info` by Jest
2. **Client Coverage**: Generated in `client/coverage/lcov.info` by Create React App's test runner
3. **Automatic Detection**: SonarQube automatically picks up both coverage files

## CI/CD Integration

### GitHub Actions Workflow

The CI pipeline generates and submits coverage to SonarQube:

```yaml
- name: Run tests with coverage
  run: |
    npm run test:ci                                    # Server tests with coverage
    cd client && npm test -- --coverage --watchAll=false  # Client tests with coverage

- name: SonarQube Scan
  uses: sonarsource/sonarqube-scan-action@master
  env:
    GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
    SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
    SONAR_HOST_URL: ${{ secrets.SONAR_HOST_URL }}
```

### Required Secrets

Configure these GitHub repository secrets:

- `SONAR_TOKEN`: Authentication token from SonarQube
- `SONAR_HOST_URL`: Your SonarQube server URL (e.g., `https://sonarcloud.io`)

## Benefits of Native Integration

### Advantages over External Services

1. **Unified Dashboard**: All metrics in one place
2. **No External Dependencies**: No need for Codecov or similar services
3. **Quality Gates**: Integrated coverage thresholds
4. **Historical Tracking**: Built-in coverage trend analysis
5. **Pull Request Integration**: Automatic PR decoration with coverage changes

### Coverage Metrics Tracked

- **Line Coverage**: Percentage of executable lines covered
- **Branch Coverage**: Percentage of branches covered in conditionals
- **Function Coverage**: Percentage of functions called during tests
- **Statement Coverage**: Percentage of statements executed

## Quality Gates

### Default Thresholds

The project enforces these quality standards:

- **Coverage on New Code**: 80% minimum
- **Duplicated Lines**: < 3%
- **Maintainability Rating**: A
- **Reliability Rating**: A
- **Security Rating**: A

### Custom Configuration

Quality gates can be customized in SonarQube dashboard:

1. Navigate to **Quality Gates** in SonarQube
2. Create or modify conditions
3. Set coverage thresholds per your requirements

## Local Development

### Running Coverage Locally

```bash
# Generate server coverage
npm run test:coverage

# Generate client coverage
cd client && npm test -- --coverage

# View HTML reports
open coverage/index.html
open client/coverage/lcov-report/index.html
```

### SonarQube Scanner (Optional)

For local SonarQube analysis:

```bash
# Install SonarQube Scanner
npm install -g sonarqube-scanner

# Run local scan (requires SonarQube server)
sonar-scanner
```

## Monitoring and Maintenance

### Regular Tasks

1. **Monitor Quality Gate**: Check SonarQube dashboard regularly
2. **Review Coverage Trends**: Ensure coverage doesn't decrease
3. **Address Technical Debt**: Fix issues identified by SonarQube
4. **Update Thresholds**: Adjust quality gates as project matures

### Troubleshooting

#### Coverage Not Appearing

1. Verify LCOV files are generated: `ls -la coverage/ client/coverage/`
2. Check SonarQube logs for parsing errors
3. Ensure `sonar.javascript.lcov.reportPaths` is correct

#### Quality Gate Failures

1. Review specific failed conditions in SonarQube
2. Check coverage percentage in detailed view
3. Verify test execution completed successfully

#### Authentication Issues

1. Verify `SONAR_TOKEN` is valid and has project permissions
2. Check `SONAR_HOST_URL` is accessible
3. Ensure organization/project exists in SonarQube

## Best Practices

### Coverage Strategy

1. **Focus on New Code**: Prioritize coverage for new features
2. **Test Critical Paths**: Ensure high-risk code has good coverage
3. **Avoid Coverage Gaming**: Write meaningful tests, not just coverage
4. **Regular Reviews**: Monitor coverage trends over time

### Integration Workflow

1. **Pre-commit**: Run tests locally before committing
2. **Pull Requests**: Review SonarQube PR decoration
3. **Merge Protection**: Require quality gate pass before merge
4. **Release Gates**: Ensure quality standards for releases

This native integration provides comprehensive code quality insights while maintaining a streamlined development workflow.
